# Задача: единая структура мастер-конспекта темы

Тема собрана из нескольких источников: слайды, записи лекций, конспекты, методички, статьи. Каждый источник уже разобран на блоки — минимальные единицы содержания с идентификаторами вида `P1.b007` (источник P1, блок 7). В `inputs/summaries.md` — аннотация, оглавление и термины каждого источника; в `inputs/blocks_index.md` — список всех блоков: идентификатор, тип, место в источнике (якорь `[[P1:p3]]`) и начало текста.

Построй структуру будущего мастер-конспекта — одного полного документа, в котором будет **вся** информация из всех источников, изложенная последовательно по логике предмета.

## Требования к структуре

1. **Логика предмета, а не источников.** Разделы идут в порядке, удобном для изучения: от понятий и определений к свойствам, теоремам, методам, примерам и приложениям. Если источники излагают одно и то же, это один раздел, а не два.
2. **Два уровня.** Главы (`level: 1`) и разделы внутри глав (`level: 2`). Глава без разделов допустима, если она короткая. Обычно 3–10 глав, в каждой 0–8 разделов. Название — по-русски, кратко и по существу; английский термин в скобках, если он есть в источниках: «Метод k ближайших соседей (kNN)».
3. **Каждый блок — в разделе.** Каждый идентификатор блока из `blocks_index.md` попадает в поле `blocks` ровно одного раздела-листа (раздела, у которого нет подразделов). Порядок блоков внутри раздела — порядок, в котором их надо излагать. Блоки разных источников об одном и том же ставь рядом: на следующем этапе они сольются в один текст.
4. **Исключения.** Блоки типа `admin` (даты, дедлайны, организационные объявления) и блоки без содержания (пустые, повтор заголовка, служебные надписи) не распределяй по разделам, а перечисли в `unassigned` с причиной. Содержательные блоки в `unassigned` не клади.
5. **Возможные расхождения.** Если источники, судя по блокам, по-разному определяют понятие, используют разные обозначения или противоречат друг другу, перечисли это в `conflict_hints`: что расходится, какие блоки, кратко в чём. Не решай расхождение — только отметь.

## Формат результата

`out/outline.json`:

```json
{
  "title": "Метрические методы классификации",
  "sections": [
    {"id": "s01", "title": "Задача классификации и гипотеза компактности", "level": 1,
     "summary": "Постановка задачи, предположения о данных", "blocks": [], "parent": null},
    {"id": "s01-01", "title": "Постановка задачи классификации", "level": 2,
     "summary": "Объекты, метки, обучающая выборка", "blocks": ["S1.b010", "P2.b003"],
     "parent": "s01"}
  ],
  "unassigned": [{"block": "S1.b001", "reason": "титульный слайд"}],
  "conflict_hints": [{"topic": "обозначение вероятности", "blocks": ["P1.b004", "S1.b012"],
                      "note": "P(A) в слайдах и Pr(A) в методичке"}]
}
```

- `id` — латиница: главы `s01`, `s02`…, разделы `s01-01`, `s01-02`…; у раздела `parent` — id главы. Порядок элементов `sections` — порядок изложения (глава, её разделы, следующая глава…).
- У главы с разделами `blocks` пустой; блоки — только у листьев.
- `title` верхнего уровня — название темы для титульной страницы.

`out/outline.md` — та же структура для человека: нумерованный список глав и разделов с одной строкой описания и числом блоков, затем список возможных расхождений.

Не пиши других файлов и не придумывай содержания: структура строится только из того, что есть в блоках.
